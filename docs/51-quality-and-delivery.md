# 《物化帝笑传》· 质量与交付计划（M5 · docs/51）

> 上游：`docs/00-brief.md`、`docs/50-engine-architecture.md`（目录、接口、参数、验收口径）。
> 本文定义「怎么把架构落地、怎么证明能交付」：任务拆解、测试策略、性能/兼容目标、里程碑、风险。
> 本轮只写文档；所有任务在文档冻结后开工，不写代码、不 `npm install`。

## 1. 目标与范围

**做什么**

- 把 `docs/50` 的架构拆成 **15 个可独立验收** 的实现任务，按依赖排序，每个任务给出文件、接口、验收、前序依赖。
- 定义测试策略：Vitest 单测范围、手动测试矩阵、性能与兼容性门槛。
- 定义里程碑 M0–M4 与退出标准、缺陷分级、交付物与演示脚本。

**不做什么**

| 不做 | 归属 |
|---|---|
| 玩法数值与 Boss 招式设计 | `docs/10` / `docs/20` / `docs/21` |
| UI 视觉稿、逐字文案 | `docs/30` / `docs/40` / `docs/41` |
| 本轮的代码/依赖安装 | 简报 §1/§9：先文档后开工 |
| 具体日历排期（无开工日期的前提下只给规模与顺序） | 本文 §3 规模口径 |

**交付物**：可运行的 `dist/` 静态站、`npm test` 通过的纯逻辑单测、手动测试记录（§5 矩阵逐项勾选）、一份 `README` 运行说明（Lead 维护）。

## 2. 机制 / 规则

### 2.1 任务定义与完成标准（DoD）

一个任务只有同时满足以下 5 条才算完成：① 文件与接口符合 §4 表中约定；② 自测通过（能演示，不靠口头）；③ 新增纯逻辑有单测（或说明为何不可测）；④ 未破坏前序任务的验收项（回归 10 分钟冒烟）；⑤ PR/提交说明写清「改了什么、怎么验」。任务粒度控制：**S** = 1–3 文件、半天内；**M** = 4–8 文件、1 天；**L** = 跨 2 个系统、需拆分；超 L 必须先拆任务再开工。

### 2.2 依赖、并行与串行规则

- 依赖关系以 §4 的任务表 + 依赖图为准；**不允许跳级实现**（如未完成 T04 手感就写 T10 Boss）。
- 可并行：T03 与 T06（输入 / 存档互不依赖文件）、T13 与 T14（HUD / 音频，文件不重叠）。
- 同一任务独占文件写入；跨任务共享文件（`main.ts`、`app/state.ts`、`content/index.ts`）的改动必须由该任务负责人合并，其他人不直接改。
- 每个任务开工前先 `read` 依赖任务的最终文件，接口签名以 `docs/50` §7 为准；发现签名需变更，先改文档再改代码。

### 2.3 缺陷分级与修复门槛

| 级别 | 定义 | 处理门槛 |
|---|---|---|
| P0 | 无法启动、白屏、存档损坏、无法通关 | 立即修，阻塞发布 |
| P1 | 核心体验错误：手感数值错、Boss 卡死、失败无法重试、金币扣款错 | 发布前必修 |
| P2 | 表现/音效/文案问题：缺占位、错位、音效缺失刷屏 | 可带 P2 发布，但需登记 |
| P3 | 建议与优化：动效打磨、非关键提示 | 进 backlog |

### 2.4 测试准入 / 准出

准入：任务自测通过 + 冒烟脚本（Title→Playing→死亡→重试）无 P0/P1。准出：§5 手动矩阵在目标设备全绿 + `npm test` 全绿 + 构建产物可跑 + 无 P0/P1 遗留。

### 2.5 Vitest 单测范围（纯逻辑，注入 `dt`/`rng`/`StorageLike`，不依赖 DOM）

| 被测模块 | 关键用例 | 数量级 |
|---|---|---|
| `systems/geom.ts` | 线段-矩形相交：穿过/相切/端点在内/零长线段 | 6 |

### 2.6 质量红线（任何一项不达标即不发布）

60fps 目标 / 首屏 3s / 无未捕获异常 / 无音频文件可通关 / 损坏存档不白屏 / 手机横屏可玩 / 键盘与触控都可完成两关。

## 3. 数值与参数表

> 玩法数值见简报 §5 与 `docs/50` §3；本表只列交付与质量门槛。

| 参数 | 建议默认值 | 单位 | 调参影响 |
|---|---|---|---|
| 实现任务数 | 15 | 个 | 少于 10 粒度过粗，多于 15 难独立验收 |

| 包体 | ≤ 700 | KB gzip | 超了先查体积，不加资源 |
| 内存峰值 | ≤ 150 | MB | 长时间游玩不增长 |
| 手动矩阵轮次 | 3 | 轮 | M2 / M3 / M4 各一轮 |

## 6. 边界与异常

| 场景 | 处理 |
|---|---|
| 某任务阻塞（依赖未就绪） | 拆出「接口桩」先行（返回占位），任务表标注真实依赖，不伪造验收 |
| 单测 flaky（时间/随机） | 纯逻辑注入 `rng` 与固定 `dt`，禁止依赖真实时钟；flaky 用例直接修或删 |
| 无音频文件环境 | T14 的验收必须覆盖「全缺」路径，禁止以「有文件」为通过前提 |
| 移动端无法真机联调 | 用同一局域网 IP + Chrome 远程调试；仍不可用时用 DevTools 设备模拟记 P2 遗留 |
| 旧机掉帧 | 触发降级（粒子上限减半/关震屏），记录机型与帧率到测试记录 |
| 无 WebGL2 | 说明页兜底，不计为失败；记录浏览器/设备 |
| 用户临时改需求 | 记入 backlog，不打断当前里程碑；影响架构的改动先回写 00-brief |
| 时间不足需裁剪 | 裁剪顺序：P3 动效 > 第二关冲击波数量 > 商店商品数；不可裁：两关通关、失败重试、存档兜底、移动端可玩 |
| 测试设备不足 | 至少覆盖：1 台 Android 中端、1 台 iPhone（或 Safari 模拟）、1 台 PC Chrome；其余记为 P2 |

## 9. 验收标准

**任务级 DoD**

- [ ] 每个任务满足 §2.1 的 5 条 DoD，且依赖任务已 complete。
- [ ] 涉及纯逻辑的任务有 Vitest 用例，`npm test` ≤ 10s 全绿。
- [ ] 每个任务完成后跑 10 分钟回归冒烟，无 P0/P1。

**里程碑级**

- [ ] M0：6 份文档齐全、冲突清单清零、拍板项有结论。
- [ ] M1：启动→移动→进房间→受伤→死亡→重试→刷新恢复全通。
- [ ] M2：第一关完整通关（含失败分支、商店购买、6s 过场）。
- [ ] M3：第二关两种失败条件可复现，碰鞋通关见「未完待续」。
- [ ] M4：§5 矩阵 12 项全绿；手机 60fps（地板 50）；首屏 ≤3s；包体 ≤700KB gzip；内存 ≤150MB 且 10 分钟不增长；无音频文件可通关。

**发布前检查**

- [ ] `npm run build` 成功，`dist/` 在子路径静态托管可跑，无 404。
- [ ] 删除音频目录后完整通关，控制台每 id 仅一条 warn。
- [ ] 损坏存档、隐私模式、无 WebGL2 三条兜底路径各验一次。
- [ ] README 步骤可从零跑通（clone → install → dev/build）。
- [ ] 版本号显示与 `__APP_VERSION__` 一致。

## 10. 风险与待确认

**风险清单**

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 数值/文案未冻结导致返工 | 中 | 中 | M0 冻结；实现只读 balance/content，不硬编码 |
| 移动端触控手感不达标 | 中 | 高 | T03 早做真机验证，热区放大、多指单独处理 |
| 旧 iOS/Android 兼容问题 | 中 | 中 | 目标 ES2020、能力探测、降级页；M4 真机跑 |
| 音频缺失路径漏测 | 低 | 高 | T14 以「全缺」为默认验收路径 |
| 时间不足导致第二关缩水 | 中 | 中 | §6 裁剪顺序，保两关可通关 |
| Vitest 作为开发依赖需确认 | 低 | 低 | 运行时依赖不变，仅 devDependencies |
| 无 WebGL2 用户无法游玩 | 低 | 中 | 说明页兜底；待拍板是否做 Canvas2D |

**待用户拍板**

1. 是否允许新增开发依赖 `vitest`（仅 `npm test` 用，不进运行时包体）？
2. 发布渠道与目标 URL 是否确定（影响 `base` 与验收环境）？
3. 失败音效文件格式/文件名（默认 `public/audio/fail.ogg`）？
4. 是否有指定必须支持的最低机型/系统版本？
